# 나의 일기장 · Firebase 버전

배포 주소: https://diary-luvicej-20261017.web.app/

구글 로그인 후 개인별 일기를 작성·조회·수정·검색·삭제합니다. Firebase Authentication은 구글 로그인만 사용하며, Firestore Standard 기본 데이터베이스는 서울(asia-northeast3)에 있습니다. 프로젝트는 결제 계정을 연결하지 않은 Spark 요금제입니다. 무료 사용량 한도 초과 시 서비스가 제한될 수 있습니다.

## 개발과 배포

Node.js 24 이상에서 `npm ci`, `npm run build`를 실행합니다. Firebase CLI로 `firebase deploy --only firestore,hosting`을 실행하면 검증된 보안 규칙과 `dist/`만 배포합니다. `.firebaserc`의 프로젝트 ID를 먼저 확인하세요.

구글 로그인은 별도로 활성화해야 합니다. 이 프로젝트는 이미 설정했습니다. 재구성할 때 Firebase Auth 설정에서 Google만 활성화하고 배포 도메인만 허용하세요. OAuth 지원 이메일이 들어간 로컬 배포 설정은 공개 저장소에서 제외합니다.

## 데이터와 보안

- 저장 위치: `users/{Firebase UID}/entries/{일기 ID}`. 제목·본문·기분·날짜·생성/수정 시각을 보관합니다.
- 인증된 구글 계정의 UID와 경로가 같은 경우에만 읽기·쓰기·삭제를 허용합니다. 필드·자료형·길이·날짜·생성 시각을 검증하고 목록 요청은 최대 200개로 제한합니다.
- 한 번에 200개씩 불러오며, 더 오래된 기록은 ‘이전 일기 더 불러오기’로 조회합니다. 검색은 불러온 기록을 대상으로 합니다.
- 로그인은 브라우저 메모리에서만 유지합니다. 새로고침·탭 종료 후에는 다시 로그인합니다. 영구 오프라인 캐시는 사용하지 않습니다.
- 저장은 서버 확인 뒤에만 완료로 표시합니다. 로그아웃하면 화면의 일기·검색어·입력 내용을 비웁니다. 공용 기기에서는 로그아웃하고 탭도 닫으세요.
- 서비스 운영자는 관리 권한으로 데이터에 접근할 수 있습니다. 종단 간 암호화는 제공하지 않습니다.
- 사용자는 일기를 직접 삭제할 수 있습니다. 계정과 전체 기록 삭제 요청 시 운영자는 Firestore의 해당 UID 일기를 먼저 삭제한 뒤 Authentication 계정을 삭제해야 합니다. Auth 계정 삭제만으로 Firestore 기록은 자동 삭제되지 않습니다.
- 기존 PC의 SQLite 일기는 자동 업로드하지 않습니다. 실제 일기나 인증 토큰을 소스·감사 자료·화면 캡처에 포함하지 않습니다.

## 검증

Java 21과 Firebase CLI의 Firestore 에뮬레이터로 `firebase emulators:exec --only firestore --project demo-classroom-diary "npm run test:rules"`을 실행합니다. 소유자 CRUD·다른 계정/비로그인 접근 차단·구글 계정 조건·필드/길이/날짜/불변 시각·목록 한도를 검증합니다.

Google 로그인 에뮬레이터를 통한 브라우저의 작성→재로그인→조회→수정→검색→삭제, 문자 그대로의 HTML 표시, 로그아웃 시 내용 비우기와 모바일 가로 넘침을 검증했습니다. 운영에서는 실제 Google OAuth 화면 연결을 확인했습니다. 운영 구글 계정으로 개인 일기를 작성하는 전 과정은 별도로 검증하지 않았습니다.

추가 의존성은 고정 버전·lockfile로 관리합니다. gRPC Node 의존성은 수정 버전 1.13.6으로 고정했고 npm audit의 알려진 취약점은 0건입니다. 규칙은 테스트 범위 내에서 검증된 프로토타입이며 모든 공격 가능성이나 운영 적합성을 보장하지 않습니다.
